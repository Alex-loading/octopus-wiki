# 安装版应用内邮箱验证码登录

## 问题与选择

管理员会话保存在当前窗口的 sessionStorage。邮箱链接在其他浏览器或邮箱内置窗口打开时，安装版应用得不到该登录会话，不能完成设备收藏授权。

增加 Supabase 邮箱 OTP 输入，在发起登录的应用窗口验证并建立会话。邮件保留链接供电脑使用；深层链接依赖系统与浏览器支持，共享管理员会话又会改变现有窗口隔离，因此采用验证码解决当前问题。

## 流程

1. 使用现有 `signInWithOtp` 发邮件，继续禁止自动创建账号并限制回跳地址。
2. 邮件模板同时包含 `{{ .Token }}` 和 `{{ .ConfirmationURL }}`。在应用内输入验证码，通过 `verifyOtp` 建立会话。
3. 共享认证状态通过 `getUser` 校验管理员身份，再返回原 `next` 页面。不会仅凭 OTP 返回的用户元数据授予管理员权限。
4. 用户在原应用启用现有 90 天设备授权。授权范围、有效期和 Cookie 设置保持现有规则。

错误验证码可修改后重试；发信成功后有 60 秒重发间隔，服务器继续执行自身限流。应用重载时可填写原邮箱并选择「已有验证码，直接输入」，避免无谓重发。验证码仅存在于当前组件内存，不写入地址栏或持久存储。

## 验证与部署

覆盖应用内验证参数、错误与过期重试、发送失败、重发间隔、已有验证码入口、管理员/普通账号的服务端身份复核及收藏参数保留。运行完整测试和生产构建。

Supabase 邮件模板需要在控制台单独保存；模板文件纳入源码用于复现。真实邮件收取与 Android 真机切换仍需设备验收，自动化不发送真实登录邮件。

本次验证：108/108 测试通过，API 类型检查和生产构建通过。Supabase 控制台预览已核对中文说明、验证码变量和登录链接，并保存模板；没有发送真实登录邮件。
