# 妙妙屋管理与真实数据展示

## 使用

- 前台保持 `/lab`，导航与页面名称统一为「妙妙屋」。首页的项目数量、前台分类与各状态数量都来自数据库中的公开项目。
- 管理员登录后，在导航点击「妙妙屋管理」（`/admin/demos`），可新增、编辑、搜索、按状态筛选和删除项目。删除前需确认。
- 标题、简介、分类、月份和封面图标必填；详情、标签、技术栈、部署链接与 GitHub 链接可选。两个链接独立填写或清空，也可以全部留空。详情留空时展示简介，标签和技术栈用中英文逗号分隔。
- 封面图标使用现有 Lucide 组件库，通过带图标和中文名称的下拉框选择 16 个预设，支持键盘选择。预览、管理列表、公开卡片和详情统一展示 SVG 图标。「简历匣」推荐使用 `FileUser`（写作与简历）。
- 数据库继续使用 `icon` 文本字段保存图标标识，无需迁移。此前的 12 个预设符号映射到对应 Lucide 图标，其他历史自定义符号保持可读，编辑时可替换。
- 项目状态为运行中、开发中、计划中，和是否公开分别设置。未公开项目仅在管理页面可见。列表按项目月份倒序排列。
- 所有项目卡片统一使用「了解更多」打开详情。详情按已填写的链接分别显示「部署链接」和「GitHub 仓库」按钮，均在新标签页打开。只填写一项就显示一个按钮，全部留空则都隐藏。链接只允许完整的 HTTP/HTTPS URL。
- 未录入项目时展示空状态，读取失败时显示重试入口。已移除静态演示项目及读取失败时的演示数据回退。

## 实现与迁移

复用现有 Supabase `demos` 表和全站管理员会话，不增加服务端密钥或新的登录方式。保留 `slug` 和文章关联兼容性，新项目自动生成内部标识。`009_wonder_room.sql` 新增 `project_url`、`is_public` 和自动更新时间触发器，并启用 RLS。游客只读公开项目，两种现有管理员声明均可管理全部项目。

已有环境先应用 `database/migrations/009_wonder_room.sql`，再发布新版前端。新环境按顺序执行全部迁移（`npm run db:init`）。首次迁移将有效的旧 `demo_url` 或 `repo_url` 转入项目链接；重新执行迁移不会恢复用户已清空的链接。迁移不插入演示项目。

部署与 GitHub 链接拆分复用 `001_content_schema.sql` 已有的 `demo_url`、`repo_url` 字段，无需新增迁移。读取旧单链接时，`github.com` / `www.github.com` 地址归入 GitHub，其余地址（含 GitHub Pages）归入部署；独立字段优先。保存时写入两个独立字段并清空旧 `project_url`，避免用户清空链接后被旧值重新填回。

前台请求显式限定 `is_public=true`，保证管理员访问前台时看到的内容与游客一致；分页读取防止数据库默认条数上限导致统计不完整。

切回浏览器页签时，Supabase 会再次发出 `SIGNED_IN`。全站会话监听对同一已验证账号采用后台权限复核，避免临时清空登录态而卸载管理表单；令牌刷新也采用相同处理。退出登录、切换账号、权限撤销或验证失败仍会取消管理访问，过期的异步结果不能恢复旧权限。这项修复保留当前已挂载表单的输入，不提供手动刷新或关闭页面后的草稿恢复。

## 验证

- `tests/frontend/demos.test.ts`：表单清理、字段校验、两个选填链接的组合、旧链接兼容与危险协议拒绝。
- `tests/frontend/demo-repository.test.ts`：公开过滤、分页、真实空结果、错误处理、管理鉴权、增删改与链接清空。
- `tests/frontend/demo-ui.test.ts`：卡片详情、双链接/单链接/无链接显示、真实空状态/失败重试、登录回跳、保存失败保留输入、新增/编辑时切回页签及令牌刷新保留表单与未保存字段、独立清空链接、编辑隐藏项目与删除确认。
- `tests/frontend/admin-session.test.ts`：后台权限复核、切换账号立即取消旧权限、退出/降权/验证失败和过期异步结果处理。
- `scripts/db/verify-wonder-room.sql`：在数据库 owner 下执行，验证游客、普通账号、伪造用户元数据和两种管理员声明的权限，最后回滚全部测试记录。
- 本次在配置的数据库内用回滚事务验证了迁移重复执行及旧链接兼容，再应用了迁移；数据库仍为 0 个项目。
- 本地 Chrome 检查真实空列表，并使用隔离预览数据检查桌面/手机排版、链接新标签页打开和 Escape 关闭详情；预览数据未写入数据库。
