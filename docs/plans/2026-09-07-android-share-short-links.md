# Android 分享文案与短链修复

## 实测原因

用户在 Android 的 bilibili、抖音、小红书中只看到平台自定义分享面板；Web Share Target 只注册系统分享目标，不能插入这些面板。主要使用路径改为复制链接后在已安装的收藏箱中粘贴，原有系统分享入口仍可用。

用户提供的小红书链接使用 `xhslink.cn`，旧版平台识别和预览白名单均未包含它。真实请求经过一次 302 跳到小红书页面，可读取标题。抖音示例经过 `v.douyin.com` → `www.iesdouyin.com` → `www.douyin.com`，最终返回 HTML，但没有可用的标题和封面元数据。两者不是同一种故障。

补充核验：用户在浏览器开发者工具中提供了 `lark:url:video_title` 和 `lark:url:video_cover_image_url` 标签，页面确实有元数据，旧解析器也漏掉了这两个名称。上文的无元数据仅指该次服务端 HTML 响应，不能概括为抖音页面没有元数据。再次请求电脑页和手机分享页，仍未获取到用户浏览器中的标签或对应视频内容。

再次报告封面为空后，使用用户的 Chrome 原生界面核对了实际视频 `https://www.douyin.com/video/7681983811227372425`。开发者工具 Elements 中存在上述两个标签，封面为带完整签名参数的 `p3-pc-sign.douyinpic.com` 图片地址。但收藏窗口地址只有 `url` 和 `title`，没有 `cover`。打开书签管理器后确认，已保存的「收藏到 Octopus」仍是只读取 `og:image` 的旧脚本。这是此次电脑书签未带入封面的直接原因；网站部署不会替换浏览器保存的书签代码。

## 修改

- 加入小红书短域名，继续逐跳检查明确允许的 HTTPS 主机，保留访问参数、超时和响应大小限制。
- 识别整段分享文案中的单个链接，以链接前文字预填标题，清除抖音复制口令和作者提示。多链接仍需用户选择，不猜标题；保留原短链，不因预览失败而阻止保存。
- 补充 Markdown 链接提取，避免将 `[链接](链接)` 拼成一个错误 URL。
- 按用户反馈移除「粘贴并识别」按钮与主动读取剪贴板逻辑。输入链接后通过「读取标题与封面」请求网页元数据，不需要额外的文案识别步骤；整段分享文案仍兼容。
- 预览可以补全文案推测的标题，但不覆盖用户手动编辑的标题。封面继续选填，部分预览成功时准确提示未读取到封面。
- 服务端预览与电脑书签按钮均支持抖音的两个 `lark:*` 标签；解码 HTML 中的 `&amp;` 后，保留封面签名参数。书签按钮可读取当前浏览器已渲染的 DOM，已有书签需要从设置页重新拖入才能使用新增元数据支持。
- Android 使用说明以复制链接、输入、读取元数据为主，明确系统分享与 App 自定义面板的区别；设置页提醒旧书签需要手动更新。

## 验证

回归测试使用用户提供的两段实际分享文案，覆盖平台分类、提取 URL 和标题、保存原短链、预览无元数据时仍可保存、手写标题保护及小红书跳转参数保留。表单测试另验证仅输入视频链接时，预览响应可填入标题与带签名的封面地址；该项使用模拟 API 响应，不代表真实抖音服务端抓取成功。

已在 Chrome 书签管理器中将用户的旧书签更新为当前代码，返回同一条真实抖音视频，从「书签」菜单点击收藏。实际收藏窗口现在包含完整 `cover` 参数，表单中的标题与封面地址均自动填入，`x-signature` 的 `%3D` 保留。没有保存测试收藏。电脑书签路径已实测通过；手机仅提交链接时的抖音服务端元数据获取仍存在前述限制。

当前完整测试 118/118 通过，API 类型检查与生产构建通过。修复后的代码真实访问小红书示例，读取到「原来真的有这样真挚且幸福的父母爱情 - 小红书」；该次响应未提供可用封面。用户提供的抖音元数据样例及浏览器书签提取测试通过；本次服务端响应仍按无元数据场景保留文案标题和原链接。
