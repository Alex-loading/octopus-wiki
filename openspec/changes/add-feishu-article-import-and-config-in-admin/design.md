## Context

当前后台文章编辑流程只支持手动输入 Markdown 正文，缺少与飞书文档转换服务的集成。已有接口包含两段能力：
- `POST /api/configs`：创建运行时配置并返回 `configId`
- `POST /api/convert`：使用 `docUrl + configId` 转换飞书文档为 Markdown

结合现有代码结构，改动会跨越页面层（`AdminArticles`）与数据访问层（`repository`），并引入浏览器本地存储（`configId`）作为导入默认上下文。约束是：保持后台 UI 与现有风格一致、避免新增复杂路由、按最小改动接入。

## Goals / Non-Goals

**Goals:**
- 在现有文章管理页面增加飞书导入区块，支持输入文档链接并一键导入覆盖正文。
- 在现有页面增加配置弹窗，支持创建/更新配置并刷新当前 `configId`。
- 将 `configId` 持久化，刷新页面后可继续导入，无需重复录入。
- 标准化 API 错误展示，统一输出后端 `code + message`。

**Non-Goals:**
- 不新增独立的配置管理页面与复杂配置列表管理。
- 不提供 `inlineConfig` 调试模式入口。
- 不实现配置历史版本、配置删除或多配置切换。
- 不调整文章保存发布的数据结构与流程。

## Decisions

1. 在 `AdminArticles` 同页新增“飞书导入”区块与“配置”弹窗
- 方案：在文章表单上方插入导入区块，包含文档链接输入框、当前 `configId` 展示、配置按钮、导入按钮；配置按钮使用现有弹窗风格组件（或同风格轻量弹层）承载配置表单。
- 原因：符合“原页面按钮+弹窗”要求，最小化路由与信息架构变更。
- 备选：新增 `/admin/feishu-configs` 页面；可扩展性更高，但改动面更大、交互跳转更重。

2. `configId` 单值持久化，更新配置即覆盖旧值
- 方案：在浏览器本地存储保存单个 `configId`（例如 `admin.feishu.configId`）；配置提交成功后以最新返回值覆盖。
- 原因：接口无配置查询与更新能力，单值策略能保证 convert 总是使用最近一次生效配置。
- 备选：维护多条配置列表；当前无后端列表接口，不适合首期。

3. 飞书导入调用固定使用 `docUrl + configId`
- 方案：`convert` 请求体只提交 `docUrl` 与当前 `configId`；若无 `configId`，在前端阻断并引导先配置。
- 原因：满足安全与生产流程，避免在前端暴露明文密钥输入用于每次转换。
- 备选：使用 `inlineConfig`；仅调试场景可用，不纳入正式后台。

4. 导入结果直接覆盖正文，不做二次确认
- 方案：转换成功后直接写入 `form.content`，并提示“正文已覆盖”；同时保留标题、摘要、标签等字段由管理员手工确认后保存文章。
- 原因：符合已确认产品行为，减少额外交互。
- 备选：覆盖确认弹窗；更安全但与需求不一致。

5. 在 `repository` 增加飞书 API 封装，页面不直接 `fetch`
- 方案：新增 `createFeishuRuntimeConfig` 与 `convertFeishuDocToMarkdown` 封装，复用统一错误映射风格，页面层仅处理状态。
- 原因：保持现有架构一致，减少页面中的请求细节和错误分支散落。
- 备选：页面内直接请求 `/api`；实现快但维护性差。

## Risks / Trade-offs

- [本地存储仅保存单个 `configId`，无法快速回切旧配置] → 在配置成功提示中展示当前 `configId`，必要时可重新创建并替换。
- [配置接口包含敏感信息，前端提交风险较高] → 强制走 HTTPS 与受控后端 `/api` 前缀，避免写入日志与持久化明文密钥。
- [导入直接覆盖正文可能误替换已编辑内容] → 按需求维持直接覆盖，并在提示文案中明确“已覆盖正文”。
- [转换接口错误码较多，前端处理分支易膨胀] → 统一抽象为“用户可读错误消息 + 原始 code”单一展示通道。

## Migration Plan

1. 在 `repository` 新增飞书配置创建与文档转换方法，并定义请求/响应类型。
2. 在 `AdminArticles` 新增飞书导入区块（输入、按钮、加载与提示状态）。
3. 新增配置弹窗与配置表单，提交后存储并回填当前 `configId`。
4. 将导入成功结果写入正文字段，并保留现有文章保存发布流程。
5. 回归验证：无配置导入、配置成功导入、更新配置后再次导入、接口失败提示。

回滚策略：若接口联调异常，可临时隐藏导入入口与配置按钮，不影响原有文章手工编辑与发布功能。

## Open Questions

- 是否需要在本期增加“清除当前 `configId`”按钮用于故障排查？
